# Name Profile Classification API

A FastAPI service for classifying a person's profile from their name. The API calls public inference services, stores the resulting profile in PostgreSQL, and exposes endpoints for creating, listing, searching, exporting, fetching, and deleting profiles.

This project was built for the HNG Stage One backend task.

## Features

- GitHub OAuth login with access and refresh tokens stored in secure cookies.
- Role-based access control for `analyst` and `admin` users.
- CSRF protection for state-changing cookie-authenticated requests.
- API version enforcement through the `X-API-Version: 1` header on profile routes.
- Request logging for method, endpoint, status code, and response time.
- Create a profile from a single `name` input.
- Call these public inference APIs:
  - `https://api.genderize.io?name={name}`
  - `https://api.agify.io?name={name}`
  - `https://api.nationalize.io?name={name}`
- Derive and store `gender`, `gender_probability`, `age`, `age_group`, `country_id`, and `country_probability`.
- Prevent duplicate profile creation for the same normalized name.
- List stored profiles with filtering, sorting, and pagination.
- Search stored profiles with a rule-based natural language parser.
- Export profile results as CSV.
- Return timestamps in UTC ISO 8601 format with a `Z` suffix.
- Use UUID v7 IDs generated by the database.

## Setup

### 1. Clone the Repository

```bash
git clone https://github.com/seyiadisa/hng14-backend-stage-one.git stage-one
cd stage-one
```

### 2. Install Dependencies

This project uses `uv` and includes a lockfile:

```bash
uv sync --locked
```

### 3. Configure Environment Variables

Create a `.env` file in the project root:

```env
DATABASE_URL=postgresql+asyncpg://username:password@host:5432/database_name

GITHUB_CLIENT_ID=your_github_oauth_client_id
GITHUB_CLIENT_SECRET=your_github_oauth_client_secret
GITHUB_REDIRECT_URI=http://127.0.0.1:8000/auth/github/callback

FRONTEND_URL=http://localhost:3000
FRONTEND_REDIRECT_URI=http://localhost:3000/auth/callback

ACCESS_TOKEN_EXPIRE_MINUTES=15
REFRESH_TOKEN_EXPIRE_MINUTES=1440

JWT_SECRET_KEY=replace-with-a-long-random-secret
JWT_ALGORITHM=HS256
```

## Authentication and Request Requirements

Authentication starts with:

```text
GET /auth/github
```

GitHub redirects back to:

```text
GET /auth/github/callback
```

After a successful callback, the API sets:

- `access_token`
- `refresh_token`
- `csrf_token`

Profile routes require:

- `X-API-Version: 1`
- an authenticated user, either through the `access_token` cookie or an `Authorization: Bearer <token>` header
- appropriate role access

Requests protected by CSRF also require:

```text
X-CSRF-Token: <csrf_token_cookie_value>
```

Role access:

- `admin`: create and delete profiles
- `analyst` or `admin`: list, search, export, and fetch profiles

## Classification Rules

- `0-12` -> `child`
- `13-19` -> `teenager`
- `20-59` -> `adult`
- `60+` -> `senior`

For nationality, the API stores the highest-probability country returned by Nationalize.

## Natural Language Parsing

The natural language search in `GET /api/profiles/search` is rule-based. It converts a plain English query into the same structured filters used by `GET /api/profiles`.

### Gender Keywords

- `male`
- `males`
- `female`
- `females`

If exactly one unique gender is found, that gender is used. If both male and female appear, no gender filter is applied.

### Age Group Keywords

- `child`
- `children` -> `child`
- `teenager`
- `teenagers` -> `teenager`
- `adult`
- `adults` -> `adult`
- `senior`
- `seniors` -> `senior`

If multiple age-group keywords appear, the last one wins.

### Age Range Keywords

- `young` -> `min_age=16`, `max_age=24`
- `above 30` -> `min_age=30`
- `over 30` -> `min_age=30`
- `older than 30` -> `min_age=30`
- `below 18` -> `max_age=18`
- `under 18` -> `max_age=18`
- `younger than 18` -> `max_age=18`

### Country Keywords

Country extraction looks for a `from ...` phrase, then matches the country phrase with `pycountry`.

Supported aliases include:

- `nigerian` -> `Nigeria`
- `kenyan` -> `Kenya`
- `ghanaian` -> `Ghana`
- `angolan` -> `Angola`
- `canadian` -> `Canada`
- `south african` -> `South Africa`
- `uk`, `britain`, `british` -> `United Kingdom`
- `usa`, `us`, `america`, `american` -> `United States`

Example mappings:

- `young males` -> `gender=male`, `min_age=16`, `max_age=24`
- `females above 30` -> `gender=female`, `min_age=30`
- `people from angola` -> `country_id=AO`
- `adult males from kenya` -> `gender=male`, `age_group=adult`, `country_id=KE`
- `male and female teenagers above 17` -> `age_group=teenager`, `min_age=17`

## Error Responses

All errors follow this structure:

```json
{
  "status": "error",
  "message": "<error message>"
}
```

Common errors:

- `400 Bad Request` -> `API version header required`
- `400 Bad Request` -> `Missing or empty name`
- `400 Bad Request` -> `Unable to interpret query`
- `401 Unauthorized` -> `Not authenticated`
- `401 Unauthorized` -> `Invalid token`
- `403 Forbidden` -> `Insufficient permissions`
- `403 Forbidden` -> `CSRF token missing`
- `403 Forbidden` -> `Invalid CSRF token`
- `404 Not Found` -> `Profile not found`
- `404 Not Found` -> `No profiles found matching the criteria`
- `422 Unprocessable Entity` -> `Invalid query parameters`
- `500 Internal Server Error` -> `Internal server error`
- `502 Bad Gateway` -> `<external API> returned an invalid response`

## External API Validation Rules

The service does not store a profile when any upstream API returns invalid data.

- Genderize must return:
  - non-null `gender`
  - non-zero `count`
  - non-null `probability`
- Agify must return:
  - non-null `age`
- Nationalize must return:
  - a non-empty `country` list
  - a top country containing both `country_id` and `probability`

If any of these validations fail, the API responds with `502 Bad Gateway`.

## Example cURL Requests

Replace `<access-token>` and `<csrf-token>` with values from a successful login.

Create a profile:

```bash
curl -X POST "http://127.0.0.1:8000/api/profiles" \
  -H "Content-Type: application/json" \
  -H "X-API-Version: 1" \
  -H "Authorization: Bearer <access-token>" \
  -H "X-CSRF-Token: <csrf-token>" \
  --cookie "csrf_token=<csrf-token>" \
  -d "{\"name\":\"ella\"}"
```

List profiles with pagination:

```bash
curl "http://127.0.0.1:8000/api/profiles?page=1&limit=10" \
  -H "X-API-Version: 1" \
  -H "Authorization: Bearer <access-token>"
```

Filter and sort profiles:

```bash
curl "http://127.0.0.1:8000/api/profiles?gender=female&country_id=US&age_group=adult&sort_by=age&order=desc" \
  -H "X-API-Version: 1" \
  -H "Authorization: Bearer <access-token>"
```

Search profiles with natural language:

```bash
curl "http://127.0.0.1:8000/api/profiles/search?q=young males from nigeria&page=1&limit=10" \
  -H "X-API-Version: 1" \
  -H "Authorization: Bearer <access-token>" \
  -H "X-CSRF-Token: <csrf-token>" \
  --cookie "csrf_token=<csrf-token>"
```

Export profiles:

```bash
curl "http://127.0.0.1:8000/api/profiles/export?format=csv" \
  -H "X-API-Version: 1" \
  -H "Authorization: Bearer <access-token>"
```

Get one profile:

```bash
curl "http://127.0.0.1:8000/api/profiles/<profile-id>" \
  -H "X-API-Version: 1" \
  -H "Authorization: Bearer <access-token>"
```

Delete a profile:

```bash
curl -X DELETE "http://127.0.0.1:8000/api/profiles/<profile-id>" \
  -H "X-API-Version: 1" \
  -H "Authorization: Bearer <access-token>"
```

## Notes

- Names are normalized before storage by trimming whitespace and converting to lowercase.
- The list and search endpoints both return paginated responses with `page`, `limit`, and `total`.
- Query validation errors return `422` with the message `Invalid query parameters`.
- Unhandled exceptions return `500` with the message `Internal server error`.
